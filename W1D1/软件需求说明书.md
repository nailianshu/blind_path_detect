## 1 引言

### 1.1 编写目的

本文档定义盲道识别系统（Tactile Paving Recognition System，以下简称 TPRS）的**功能需求、性能需求、接口需求与运行环境要求**，作为后续系统设计、编码实现、测试验收的依据。

本文档的预期读者包括：

### 1.2 项目背景

| 项 | 说明 |
| :--- | :--- |
| **系统名称** | 盲道识别系统（TPRS） |
| **系统形态** | PyQt5 桌面应用 + Ultralytics YOLO 推理引擎 |
| **核心技术** | 基于 YOLO 的实例分割（Instance Segmentation） |
| **开发语言** | Python 3.9+ |
| **推理后端** | Ultralytics YOLO（PyTorch / MPS 加速） |

**问题背景**：视障人士依赖盲道出行，但现实中盲道普遍存在**被占用、被遮挡、破损、铺设中断或缺失**等问题。传统盲杖无法识别盲道的类型与走向，也无法感知前方是否存在障碍物，导致视障人士难以判断行进方向与风险。

**现有方案的不足**：

1. 传统图像处理方法依赖手工特征，对光照、角度、材质变化鲁棒性差；
2. 纯目标检测（bounding box）只能给出矩形框，无法刻画盲道的不规则走向与区域范围；
3. 缺少对盲道状态（缺失、被占用）的智能判定能力。

**本系统的定位**：通过实例分割获得盲道的**像素级轮廓**，基于盲道面积占比智能判断盲道缺失与障碍物风险，为视障人士提供可理解的方向引导与风险提示。

### 1.3 术语与定义

| 术语 | 定义 |
| :--- | :--- |
| **盲道（Tactile Paving）** | 铺设于人行道上、通过凸起纹理为视障人士提供触觉引导的设施 |
| **盲道缺失** | 画面中盲道面积占比低于阈值（< 2%），判定为未检测到有效盲道 |
| **疑似障碍** | 画面中盲道面积占比偏低（2%~5%），可能存在障碍物遮挡 |
| **实例分割** | 对图像中每个目标同时给出类别与像素级轮廓的任务 |
| **mAP@0.5** | IoU 阈值为 0.5 时的平均精度均值，衡量检测/分割精度 |
| **mAP@0.5:0.95** | IoU 阈值 0.5~0.95 步长 0.05 的平均值，更严格的精度指标 |
| **P95 时延** | 95% 的请求能在该时间内完成，用于衡量时延稳定性 |
| **面积占比** | 盲道分割掩膜面积占画面总面积的比例，用于判定盲道状态 |

## 2 任务概述

### 2.1 系统目标

TPRS 的总体目标是：**在桌面端对图像 / 视频 / 摄像头画面中的盲道进行实时分割与状态识别，并以可视化与语音方式向使用者输出引导信息。**

具体目标分解如下：

| 编号 | 目标 | 说明 |
| :--- | :--- | :--- |
| G-01 | 盲道区域像素级分割 | 输出盲道轮廓掩膜，而非仅矩形框 |
| G-02 | 盲道状态判定 | 基于面积占比判定盲道缺失、疑似障碍、正常等状态 |
| G-03 | 方向引导 | 计算盲道偏移量与方向角，提供方向引导 |
| G-04 | 语音告警 | 异常状态持续时触发语音播报，带冷却机制避免重复 |
| G-05 | 实时性 | 端到端处理满足实时交互要求 |
| G-06 | 本地化部署 | 全部推理在本机完成，不上传用户图像 |

### 2.2 用户特点

| 用户类型 | 特征 | 对系统的要求 |
| :--- | :--- | :--- |
| **视障人士（主要使用者）** | 依赖听觉与触觉，无法操作复杂界面 | 语音播报清晰、界面极简、可一键启动 |
| **家属 / 陪护人员** | 有一定操作能力，需了解检测结果 | 界面可视化清晰、结果可回看 |
| **研究人员 / 开发者** | 需要调试模型与查看数据 | 提供参数配置、性能监控、图片分析能力 |

### 2.3 假定与约束

| 类型 | 内容 |
| :--- | :--- |
| **假定 A-01** | 输入图像为白天或光照充足的户外人行道场景 |
| **假定 A-02** | 摄像头视角为行进方向正前方，俯仰角在合理范围内 |
| **假定 A-03** | 盲道材质为国内标准规格（黄色 / 灰色凸起纹理） |
| **约束 C-01** | 系统须在**无网络**环境下可完整运行（Flask 远程监控除外） |
| **约束 C-02** | 首期部署目标为 Apple Silicon（MPS 加速），兼容 CPU 环境 |
| **约束 C-03** | 模型体积须控制在可随应用分发的范围内（≤ 50 MB） |
| **约束 C-04** | 数据集标注格式须兼容 YOLO 原生格式 |
| **约束 C-05** | 系统须运行于 macOS / Windows 桌面平台 |

| 类别 ID | 类别名称 | 说明 |
| :--- | :--- | :--- |

### A.4 核心算法说明

#### A.4.1 盲道状态判定算法

当前版本采用**面积占比**判定盲道状态，而非多类别检测：

| 状态 | 判定条件 | 告警类型 | 语音提示 |
| :--- | :--- | :--- | :--- |
| 盲道缺失 | 面积占比 < 2% | area_missing | "盲道缺失，请小心前行" |
| 疑似障碍 | 面积占比 2%~5% | area_obstacle | "盲道可能有障碍物，请注意" |
| 居中 | 面积占比 ≥ 5%，偏移 < 阈值 | 无 | 无 |
| 偏移 | 偏移量超过阈值 | offset_left/right | "偏移过大，请调整方向" |
| 严重偏移 | 偏移量严重超过阈值 | offset_severe | "严重偏移，请立刻调整" |

#### A.4.2 告警冷却机制

- 冷却时间：5 秒
- 逻辑：同类告警触发后进入冷却期，冷却期内不重复播报
- 目的：避免语音打断，提升用户体验

#### A.4.3 基于时间的状态机

- 异常状态需持续超过阈值时间（默认 2 秒，可配置）才触发告警
- 触发后必须恢复正常状态，才能再次累积
- 避免单帧误检导致的频繁告警
